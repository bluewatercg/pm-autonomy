# 历史项目集成独立PM

## 使用边界
读取 references/PLAN.md，按 assets/checklist.md 验证阶段。把技能作为集成流程，不当作运行时安装或生产切换授权。保留原项目和历史，默认只读盘点；执行用户已授权的隔离试点，不把该授权扩大到生产迁移。

## 执行流程
1. 确认根目录、负责人、现役服务、旧PM写入口及并发写者。记录时刻、实际HEAD、工作树、版本、端口及关键摘要；索引损坏时停止依赖索引操作，不擅修。未知如实标记。
2. 读取有效约束与登记，区分冻结证据、追加账本、普通配置。禁止覆盖历史或重算被改冻结文件摘要冒充原件。迁移复制原字节和来源，转换建successor。
3. 建立独立候选与影子模式，仅导入和提出建议，不派业务执行、不代替旧PM写状态。记录旧ID到新ID映射、来源摘要、观测时点及可信程度，禁止从自报推断验收。
4. 分类历史任务：已验收只引用；未知保持unknown；在途留旧系统完成或明确暂停移交；部分交付按验收项登记accepted/remaining/transferred。新优化新建关联任务，不重写旧承诺。
5. 提出单写移交方案，明确任务/文件/状态的写入所有者。实施可信租约或经独立核验的旧入口停写和新入口启用机制；机制不存在或停写未证实则阻塞。切换期间不重复派活。
6. 选一个低影响、可隔离的新任务试点。绑定真实基线、独立worktree、审批主体、scope/actions/expiry；沿用新项目技能的角色分工、三architect触发、独立验收和恢复纪律。
7. 核验并发漂移、旧入口拒绝写、新入口合法写、非法授权拒绝、相同request幂等及恢复。运行历史回归和服务观测；时点MATCH不证明期间未变。
8. 逐步扩大接入范围，每批单独映射、授权、验收和记录写入所有者。代码合并、运行时激活、业务发布分别审批；旧服务重启、账户、数据库迁移不自动包含。
9. 回退时先阻塞新派发、核验在途、归档新证据、撤销新授权，再明确移交旧入口。不得简单同时启动新旧写者，不删除失败现场或回退并发业务修改。

## 必须阻塞
遇到未知在途执行、无法隔离、有效规则冲突、基线漂移未裁决、旧写者未停、审批不可信、恢复无法确定结果时暂停受影响范围。外部调用未知保持blocked_unknown。配置和提示词不等于硬闸门；模型角色不授予权限。

## 交付
输出只读盘点、ID映射、状态可信度、逐范围写入所有权、移交/回退方案、试点卡、原始测试证据、剩余与范围扩展建议。不宣称历史全量已验收或已生产激活。保留用户已有授权，仅新增范围和不可逆动作另行确认。
